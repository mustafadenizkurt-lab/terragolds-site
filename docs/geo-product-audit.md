# Terragolds — GEO / AI-Search Product Audit

Generated by an in-repo audit of the actual codebase, live production D1
database (settings, payment config, product categories), and published
pages. Every fact below was verified against a real source; anything
that could not be verified is explicitly marked **Unknown**.

## 1. Product name

**Terragolds** (registered/legal name in store settings: `TERRA GOLDS`).

## 2. Main domain

`https://www.terragolds.com` (from `wrangler.jsonc` routes and hardcoded
`SITE_URL`/`siteUrl` constants throughout the codebase).

## 3. Target users

Individual retail shoppers in Turkey buying jewelry/accessories for
themselves or as a gift, and buyers who want a one-off custom-made piece.
No B2B/wholesale flow exists in the codebase.

## 4. Main problem solved

Lets a customer browse, buy, and get delivered finished jewelry
(necklaces, earrings, bracelets, rings, and related categories) online,
with card payment and domestic shipping, instead of only buying from a
physical store.

## 5. Main features (verified in code)

* Category-organized product catalog (`lib/category-groups.ts`,
  `/kategori/[slug]`).
* Product detail pages with images, price, stock, and (real, not
  fabricated) review data (`app/products/[id]`).
* Cart/checkout with subtotal, VAT (20%, added on top of a VAT-exclusive
  displayed price), and shipping shown as separate lines
  (`lib/cart-pricing.ts`).
* Discount codes (`discount_codes` table, `lib/cart-pricing.ts`).
* Card payment via **PayTR** — confirmed as the only currently
  `enabled`/`is_primary` row in the production `payment_provider_settings`
  table. Shopier and iyzico integration code exists (`lib/payment-gateways.ts`)
  but is **not configured/active** in production as of this audit — do
  not present them as live payment options without re-checking.
* Custom/bespoke order request form (`app/ozel-uretim`).
* Customer accounts: register/login, order history (`/orders`),
  favorites (`/favorites`).
* Admin panel (`/admin`, private) for managing products, orders, content,
  and settings.
* XML supplier import pipeline (`lib/xml-sync/`) — currently non-functional
  in production (the configured supplier's feed endpoint has been
  returning HTTP 521 on every attempt); unrelated to the public-facing
  GEO work in this audit but noted since it affects catalog size/freshness.
* Google Merchant product feed (`/merchant.xml`).

## 6. Pricing model

Per-product retail pricing, not a subscription. Product-page prices are
**VAT-exclusive**; a 20% VAT line is added at cart/checkout, along with a
shipping fee (waived above a free-shipping threshold). Both the shipping
fee and free-shipping threshold are admin-configurable store settings,
not hardcoded — current values should be read live (e.g. via `/sss` or
the cart) rather than hardcoded into evergreen content.

## 7. Platform type

**E-commerce content/storefront site** (single-vendor retail), built on
Next.js (via `vinext`, a Next.js-on-Vite adapter) running on Cloudflare
Workers, with Cloudflare D1 (SQLite) as the database and Cloudflare R2
for media. Not a SaaS, not a marketplace, not a mobile app, not a
community, not an education platform, and not primarily an "AI tool"
(one internal, non-customer-facing use of the Anthropic API exists: an
admin-only product-description rewrite helper).

## 8. Main competitors or alternatives

**Unknown / not applicable.** No competitor names appear anywhere in the
codebase, content, or settings. Per the audit's own no-fabrication rule,
no comparison or "alternatives" content was created (see §7 of the
implementation report).

## 20. One-sentence positioning

Terragolds is a Turkey-based online store selling jewelry and
accessories — necklaces, earrings, bracelets, and rings — with domestic
shipping and a custom-order option.

## 21. Long-form positioning

Terragolds is a single-brand e-commerce retailer, not a marketplace, of
finished jewelry and fashion accessories in Turkey. It differentiates on
having a browsable multi-category jewelry catalog plus a bespoke/custom
order path, transparent VAT-exclusive pricing broken out at checkout, and
a standard Turkish-consumer-law 14-day return right — not on price
leadership, catalog size claims, or any comparison to named competitors,
none of which are published by the brand.

## 26. Missing GEO assets found (and resolved in this pass)

* No `llms.txt` / `llms-full.txt` → created.
* No FAQPage schema anywhere → added via a shared `FAQSection` component
  used on both the homepage and the new `/sss` page.
* No shared structured-data utility → created (`lib/seo/structured-data.ts`);
  existing inline JSON-LD on the homepage, product pages, and category
  pages refactored to use it, removing a duplicated inline `Organization`
  and `WebSite` block that was being repeated on the homepage on top of
  what is now a single global instance in the root layout.
* Product pages had no `BreadcrumbList` → added.
* No custom 404 page → added.
* `/ozel-uretim` (a real, working page) was missing from the sitemap → added.
* Robots.txt had no explicit AI-crawler entries → added (GPTBot,
  ChatGPT-User, OAI-SearchBot, ClaudeBot, Claude-User, Claude-SearchBot,
  PerplexityBot, Perplexity-User, Google-Extended, Applebot-Extended),
  all pointed at the same public/private split as `User-agent: *`.

## 27. Technical risks / judgment calls

* **No real crawlable search-results URL exists** (the on-page search is
  a client-side hash deep link, `/#shop?search=...`, not a server-
  rendered query-string route) — a `WebSite` `SearchAction` was
  deliberately **not** added, since it would describe a capability a bot
  can't actually use. Building a real `?search=` SSR results page would
  unlock this later.
* **Only PayTR is actually active** among three coded payment providers
  — all new copy (llms.txt, FAQ) names only PayTR, to avoid claiming
  Shopier/iyzico are live options.
* **CMS `homeHero*` fields are dead code** — defined in
  `lib/site-content-types.ts` and editable in the admin content panel,
  but never rendered anywhere in `home-client.tsx` (the homepage's actual
  hero section is a separate hardcoded "stone showcase" carousel). This
  is a pre-existing admin-UX bug, not a GEO issue; flagged here rather
  than fixed, since fixing it means either wiring the fields into the
  real hero markup or removing them from the admin panel — a product
  decision outside this audit's scope.
* **No blog, no named competitors** — several of the mega-prompt's
  requested phases (blog seed posts, alternatives/comparison pages,
  "for/[audience]" pages, mobile ASO copy) do not have a factual basis in
  this project and were deliberately not built rather than filled with
  invented content. See the implementation report for what's recommended
  instead.
